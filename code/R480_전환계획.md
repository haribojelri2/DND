## 4-1. 사이트 도면 실측 (Testbed Layout 260410, R450) — 2026-08-19

| 항목 | 값 |
|---|---|
| 입력 | LINE 42 + ARC 84, 호 전부 r=450.0, 스윕각 45°×24 / 90°×60 |
| 레이어 | `[SKH] OHT Rail` 하나 (색/레이어 필터 불필요) |
| ori | NODE 132 / LINK 168 — L24 N12 R24 S102 U6 |
| final | NODE 233 / LINK 269 — L8 N12 R24 S211 U14 |
| 복합분기 | 4개 — `pair_X=2820` / `armX=1920` / `topline=2820` (**armX = pair_X − 2R**) |

**등가성 확인**: 편집 전 코드 vs 현재 코드(`rail_arc_radius_mm=450`) → ori·final 맵 **md5 완전 동일**.
ori U 6개·N 12개를 실제로 타는 도면이라, 앞서 "도면이 빈약해 미검증"이던 구멍이 메워졌다.

**설정 450 vs 480 (같은 R450 도면) → 출력 동일.** 이유 둘:
- ori U 게이트는 **상한**이라 950→1010 은 더 관대해질 뿐 (폭 900 U 는 양쪽 통과)
- 직-호-직 U 반지름 매처가 **0개** 적중 — 이 도면엔 180° 호가 없다(45°/90°만).
  파서가 ≥180° 호를 파싱 시점에 쪼개므로 이 경로 자체가 잘 안 탄다.

**정정 — 복합분기는 R 전환에 영향 없다**
- Point A 조건은 `armX ∈ [1795, 1805]` 인데 실측 armX = **1920** → R450 에서도 **원래 발동하지 않는다**.
  R480(레일 간격 2820 고정 시 armX = 2820−960 = 1860)에서도 창 밖 → 거동 불변.
- Point B2(2100)도 1920→1860 둘 다 미만 → 중간 1분할 그대로.
- 따라서 **1795 / 2100 은 재계산 불필요**. 단 Point A 가 이 레퍼런스 도면에서 한 번도 발동하지
  않는다는 건 별개 의문 — 어떤 도면 기준으로 넣은 값인지 확인 필요.

**DWG 입력 시**: `accoreconsole` 을 **PowerShell 에서 절대경로로** 호출해야 한다.
Bash(MSYS)로 넘기면 인자가 깨져 usage 만 찍고 빈 도면을 열어버린다.
